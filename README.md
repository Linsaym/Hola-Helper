# Hola Helper 🎙️

Локальный голосовой ассистент для Windows на Rust. Распознаёт фразу **«Hey Jarvis»** через [openWakeWord](https://github.com/dscripka/openWakeWord), отвечает заранее записанной голосовой фразой и слушает команду на русском через [whisper-rs / whisper.cpp](https://docs.rs/whisper-rs/0.16.0/whisper_rs/).

**Работает офлайн:** для распознавания и воспроизведения интернет не нужен.

## Быстрый старт

Из корня проекта:

```powershell
cargo run --release -- --mic
```

Сначала установи модели и инструменты сборки, описанные ниже. Скажи **«Hey Jarvis»**, дождись окончания ответа из `assets/voice/wake/` и скажи **«Давай поиграем»**. Ассистент откроет существующий ярлык `actions/steam.lnk` через Windows Shell. В Windows регистр имени файла не имеет значения: `Steam.lnk` тоже подходит.

Максимальная запись команды — 3 секунды; отсчёт начинается после окончания голосового ответа и очистки накопленного аудио. Пауза в 0,8 секунды завершает команду раньше. Простой порог громкости отсекает тишину и короткие щелчки; слишком тихая речь может быть пропущена. После действия или голосового ответа ассистент снова ждёт wake word. При отсутствии речи возвращается к ожиданию без ответа.

Для остановки нажми **Ctrl+C**.

> Порог срабатывания: **0.25**. Чем он ниже, тем выше чувствительность, но тем больше риск ложных срабатываний.

## Голосовые ответы

Помести свои записи в папку:

```text
assets/
└── voice/
    ├── wake/
    │   ├── listening.wav
    │   ├── command.wav
    │   └── whats-up.wav
    ├── fail/
    │   └── 1.wav
    └── success/
        ├── steam1.wav
        ├── steam2.wav
        ├── random1.wav
        └── random2.wav
```

После обнаружения ключевой фразы приложение случайным образом выбирает один из WAV-файлов **непосредственно в этой папке**. Подойдут обычные PCM WAV, воспроизводимые Windows.

Если речь была, но текст не удалось распознать, ближайшая команда не прошла порог, совпадение неоднозначно или действие завершилось ошибкой, воспроизводится случайный WAV из `assets/voice/fail/`. При ошибке STT также звучит ответ из `fail`. Если речи не было (включая результат Whisper «нет речи»), ответа нет.

После успешного запуска действия выбирается случайный персонализированный WAV из `assets/voice/success/`. Имя состоит из значения `action` в `commands.json` и номера: для `steam` — `steam1.wav`, `steam2.wav`; для `vscode` — `vscode1.wav`, `vscode2.wav`. Если таких файлов нет, выбирается случайный общий ответ `random1.wav`, `random2.wav` и т. д. Регистр имени и расширения WAV не учитывается. Номера не обязаны идти подряд; количество файлов не ограничено кодом. Имена без номера и файлы других действий не выбираются.

Если подходящих ответов или папки `success` нет, работа продолжается без голосового ответа. Ошибка чтения или воспроизведения выводится как предупреждение `[voice]`.

Пока звучит любой ответ, входящий звук отбрасывается. После воспроизведения накопленное аудио очищается. После ответа из `wake` начинается запись команды, после ответа из `fail` или `success` ассистент возвращается к wake word. Это предотвращает распознавание собственного ответа ассистента.

Если записей нет или воспроизведение не удалось, программа выводит предупреждение `[voice]` и продолжает работу.

## Проверка на WAV-файле

```powershell
cargo run --release -- samples/heyjarvis.wav
```

Тестовый входной файл должен быть **WAV PCM 16-bit, mono, 16 kHz**. Этот режим проверяет только wake word и голосовой ответ, выводит факт обнаружения и максимальный `score`. STT и действия доступны в режиме `--mic`.

## Установка моделей

Для распознавания нужны три ONNX-файла в `models/openwakeword/`. Если их ещё нет, выполни в PowerShell из корня проекта:

```powershell
New-Item -ItemType Directory -Force models/openwakeword | Out-Null
$release = 'https://github.com/dscripka/openWakeWord/releases/download/v0.5.1'
foreach ($name in @('melspectrogram.onnx', 'embedding_model.onnx', 'hey_jarvis_v0.1.onnx')) {
    Invoke-WebRequest "$release/$name" -OutFile "models/openwakeword/$name"
}
```

Для команд нужна **мультиязычная Base** (не `base.en`) в `models/whisper/ggml-base.bin`, около 148 MB:

```powershell
New-Item -ItemType Directory -Force models/whisper | Out-Null
curl.exe --fail --location 'https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.bin' --output models/whisper/ggml-base.bin
```

Модели не хранятся в Git. Приложение не скачивает их автоматически и не обращается к сети. Whisper загружается один раз перед запуском микрофона, остаётся в памяти и использует CPU с максимум четырьмя потоками. Язык задан явно: `ru`; перевод и перенос текста предыдущей команды отключены. Python для запуска не требуется.

## Сборка в Windows

Для `whisper.cpp` нужны Visual Studio C++ Build Tools, CMake и `libclang` для генерации bindings: [инструкция whisper-rs](https://github.com/tazz4843/whisper-rs/blob/master/BUILDING.md). Если CMake и LLVM установлены отдельно, добавь CMake в `PATH` и укажи каталог с `libclang.dll` в `LIBCLANG_PATH`.

В текущем окружении можно использовать CMake из Visual Studio и `libclang` из существующего Python venv. Выполни в PowerShell из корня проекта перед сборкой:

```powershell
.venv/Scripts/python.exe -m pip install libclang
$vswhere = "${env:ProgramFiles(x86)}/Microsoft Visual Studio/Installer/vswhere.exe"
$visualStudio = & $vswhere -latest -products '*' -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
$env:CMAKE = Join-Path $visualStudio 'Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe'
$env:LIBCLANG_PATH = (Resolve-Path '.venv/Lib/site-packages/clang/native').Path
cargo run --release -- --mic
```

Эти переменные действуют в текущем окне PowerShell. Если `.venv` ещё нет, создай его командой `python -m venv .venv`. Не задавай `WHISPER_DONT_GENERATE_BINDINGS`: готовые bindings версии 0.16.0 вызывают ошибки размеров структур на Windows. Инструменты сборки не нужны при запуске готового `.exe`.

В `.cargo/config.toml` явно заданы `/O2 /DNDEBUG` для Release-сборки C- и C++-частей Whisper под MSVC. Это предотвращает потерю оптимизаций при передаче флагов из `cmake-rs`: без этих настроек даже `cargo build --release` мог собирать нативную библиотеку без оптимизации. Модель Base, полный аудиоконтекст и параметры декодирования сохраняются.

Если Whisper был собран до появления этих настроек, один раз пересобери именно его release-артефакты (в окне PowerShell с настроенными инструментами сборки):

```powershell
cargo clean --release -p whisper-rs-sys
cargo build --release
```

## Как это устроено

```text
Микрофон → обработка аудио → openWakeWord → «Hey Jarvis»
                                              ↓
                                  Случайный WAV-ответ
                                              ↓
                                  Запись команды (mono, 16 kHz)
                                              ↓
                                  Whisper Base, ru → текст
                                              ↓
                                  Нормализация → Левенштейн (max_distance)
                                              ↓
                                  Действие из actions/ → ожидание wake word
```

- **CPAL** получает звук с микрофона Windows.
- Аудио преобразуется в mono, 16 kHz; распознавание выполняется отдельно от микрофонного callback.
- **ONNX Runtime** запускает модели openWakeWord на CPU.
- **Windows MCI** воспроизводит заранее записанные ответы.
- **Whisper** выполняет STT в отдельном потоке только после активации и записи команды. Во время STT аудиоочередь продолжает опустошаться, повторная активация отключена.
- `command_audio` ограничивает запись по длительности и паузам; `speech` отвечает за STT; `commands` сопоставляет текст; `actions` выполняет действие.

Регистр и пунктуация нормализуются, затем пробелы удаляются. По расстоянию Левенштейна между Unicode-символами выбирается ближайшая фраза из конфигурации. Если расстояние больше `max_distance` или несколько фраз одинаково близки, действие не выполняется. Отрицания и отдельные слова специально не проверяются: решение зависит только от расстояния. Тишина и сегменты с высокой вероятностью отсутствия речи ничего не запускают. Распознанный текст не передаётся в командную оболочку: запускается только локальный файл действия, выбранного через конфигурацию.

## Настройка команд

В режиме `--mic` файл `config/commands.json` читается **один раз при запуске**, до загрузки моделей и открытия микрофона:

```json
{
  "max_distance": 6,
  "commands": [
    {
      "phrase": "давай поиграем",
      "action": "steam"
    }
  ]
}
```

`max_distance` — целое неотрицательное число; `0` разрешает только точное совпадение после нормализации. `phrase` — произносимая фраза. `action` — имя файла в `actions/` без расширения. Для `steam` подойдут `Steam.lnk`, `steam.LNK` или `STEAM.bat`; регистр имени и расширения не учитывается. Рабочая директория запускаемого файла — `actions/`.

Чтобы добавить команду, добавь объект в `commands` и соответствующий `.lnk` или `.bat` в `actions/`, затем перезапусти приложение. **Перекомпиляция не требуется.** Распознаватель хранит настройки и нормализованные фразы в памяти, а файлы действий ищутся непосредственно перед запуском.

Если одновременно найдены, например, `Steam.lnk` и `steam.bat`, выводится ошибка неоднозначности и ничего не запускается. Поиск ведётся только в самой папке `actions/`, без обхода подкаталогов. Абсолютные пути, разделители каталогов, `..`, альтернативные потоки Windows и недопустимые имена запрещены. Канонический путь найденного файла должен оставаться внутри канонического каталога `actions/`, включая проверку файловых символических ссылок.

Отсутствующий или некорректный JSON, неизвестные поля, неверные типы, пустые фразы и дубликаты фраз после нормализации приводят к понятной ошибке при старте. Пустой массив `commands` разрешён и отключает все команды. Равные минимальные расстояния между разными фразами обнаруживаются во время распознавания: действие не выбирается. Ошибка поиска или запуска файла действия обрабатывается через существующий ответ из `assets/voice/fail/`, после чего продолжается ожидание wake word.

После изменения исходников пересобери приложение: `cargo check` и `cargo test` не обновляют `target/release/hola-helper.exe`. Используй `cargo run --release -- --mic` с настроенными инструментами сборки либо `cargo build --release`, затем запускай новый `.exe`. В логе выводятся исходная фраза с экранированием скрытых символов, выбранная команда (или `None`) и минимальное расстояние Левенштейна. Для пустого текста или списка команд расстояние обозначается `n/a`.

Дополнительно выводятся время распознавания STT, время сопоставления фразы и длительность запроса запуска действия. Последняя включает поиск файла и вызов Windows Shell, а время открытия окна самой программы зависит от запускаемого приложения.

## Проверка проекта

```powershell
cargo fmt --check
cargo check
cargo test
```

Для измерения задержки STT на одном WAV после однократной загрузки Base:

```powershell
$env:HOLA_TEST_COMMAND_WAV = 'C:/path/to/steam-command.wav'
cargo test --release speech::tests::benchmark_command_recognition_latency -- --ignored --nocapture
```

Тест выполняет четыре распознавания и выводит длительность аудио, время обработки и текст. Действия не запускаются. Без `HOLA_TEST_COMMAND_WAV` используется `samples/heyjarvis.wav`. Для сравнения скорости и текста используй одинаковые запись и параметры на одной машине.

Дополнительные тесты с моделями и примером записи:

```powershell
cargo test wake_word::tests -- --ignored
cargo test microphone::tests::recorded_audio -- --ignored
cargo test speech::tests::silence_does_not -- --ignored
```

Проверка STT на собственной записи первой фразы из конфигурации (**WAV PCM16, mono, 16 kHz**), затем на тишине с той же загруженной моделью:

```powershell
$env:HOLA_TEST_COMMAND_WAV = 'C:/path/to/steam-command.wav'
cargo test speech::tests::recognizes_recorded_command_then_silence -- --ignored --nocapture
```

Отдельная проверка запуска **действительно выполняет первое настроенное действие** (в исходной конфигурации открывает Steam):

```powershell
cargo test actions::tests::configured_action_launches -- --ignored
```

Проверка голосового ответа при неудаче **воспроизводит WAV через устройство вывода Windows**:

```powershell
cargo test voice::tests::bundled_failure_response_plays -- --ignored
```

Проверка ответа об успехе для первого действия из конфигурации также **воспроизводит WAV через устройство вывода Windows**, без запуска действия:

```powershell
cargo test voice::tests::configured_success_response_plays -- --ignored
```

При проблемах с микрофоном проверь доступ Windows к микрофону и используй **release-сборку**. Предупреждение `Xrun` означает возможный пропуск аудиоданных; приложение пытается продолжить захват. При смене или отключении устройства может потребоваться перезапуск.
